## 결론

비밀 가리기·삭제 전 보관·세션+커밋 결합·기간 요약은 경쟁 서비스에도 있어 더는 차별점이 아니에요. 남는 것은 "여러 저장소의 커밋과 세션을 하루·프로젝트별 한 파일로, 쓰기 전에 가려, 내 컴퓨터에서 AI·네트워크 없이"라는 **조합**과 `check`·`redact`인데, 이것도 위협 1위 Entire `recap`의 세부(?)에 달려 있어요. PRD 2장·README 비교 표의 세 문장은 리서치와 맞지 않아 먼저 고쳐야 해요.

## 서비스별 강점·약점

- **SpecStory** 강점: 에이전트 10개·세 OS, 자동 저장·`search`, 설치 232,326(자체 집계).
  약점: 세션마다 md라 날짜별 정리·git 연동이 없어요.
- **Entire** 강점: 세션·커밋을 가장 깊게 묶고(`blame`·`why`) 가리기가 9겹이에요. 별 5.2k, 6천만 달러 시드.
  약점: 체크포인트가 저장소 안에 있어 기본으로 push되고, 여러 저장소는 계정이 필요해요.
- **receipts** 강점: Anthropic 공식, `/plugin install` 한 줄, 과장 없는 매니저용 문구를 줘요.
  약점: 하루별·가리기·보관이 없고 세션 없는 저장소는 안 봐요. 설치 195, Windows 동작 ?.
- **cc-worklog** 강점: 하루·프로젝트별 한 파일에 세션과 여러 저장소 커밋, `check`·`redact`, 네트워크 0.
  약점: 배포 전이라 사용자가 없고, 실행을 잊으면 30일 뒤 기록이 지워지며, 주간 정리·문장 요약이 없어요.

## cc-worklog에 주는 의미

**지킬 차별점** (가리기·보관·세션+커밋·기간 요약 그 자체는 이제 아니에요. 자동 보관은 오히려 뒤져요)
1. 하루·프로젝트별 한 파일에 세션과 여러 저장소 커밋(세션 없던 저장소·손으로 한 커밋 포함). Entire `recap`이 ?라 잠정이에요.
2. 저장소 밖 내 컴퓨터에만, AI·네트워크 0(기본 동작 기준 cc-worklog만 ○).
3. `check`·`redact`·경로 속 사용자 이름 가리기. 경쟁 쪽은 리서치에 안 나왔을 뿐 없다는 확인은 아니에요.

**조심할 위협**
1. **Entire(1위, 가능성 높음·추정)**: `recap`이 로그인·LLM 없이 여러 저장소의 하루별 md를 내면(이미 그렇다면) 차별점 1이 거의 사라져요. 릴리스가 이틀 연속이고 자금이 커요.
2. receipts(중간·추정)는 하루별 출력이 더해지면 일부 겹쳐요. SpecStory는 낮음~중간(추정)이에요.

**할 일**
1. PRD 2장·README 표의 세 문장 고치기: SpecStory "비밀 가리기 없음"(일부 틀림), Entire "커밋 단위만"(틀림), 가리기는 "올리거나 넘기기 직전에만"(틀림). 차별점은 조합으로 좁히고 뒤지는 칸도 표에 둬요.
2. 자동 보관의 가벼운 형태(I-22)를 다음 1순위로.
3. Entire `recap` 세부 리서치 보강, 예정 A19·A20 먼저 구현, A18 위에 AI 없는 주간 묶음(I-23).
