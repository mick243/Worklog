## 1. 타깃 사용자

- 누구인가: Claude Code로 하루에 여러 저장소를 오가며 일하는 개발자예요. 업무일지·주간 보고·회고·포트폴리오 정리처럼 "그날 무엇을 했는지"를 글로 남겨야 하고, 회사 코드나 비밀 값이 섞인 대화 내용을 외부 AI 서비스로 보내기 꺼리는 사람이에요. 공개 도구라서 npm으로 설치해 쓰는 다른 Claude Code 사용자 모두가 대상이에요.
- 지금은 이 일을 어떻게 하고 있나:
  - 저장소마다 `git log`를 따로 보거나, git-standup 같은 도구로 커밋만 모아 봐요.
  - 세션 기록은 claude-code-log 같은 뷰어로 세션을 하나씩 열어 훑거나, Claude에게 "오늘 한 일 정리해 줘"라고 시켜요. 이때 대화 내용이 다시 모델로 가요.
  - AI 일지 플러그인을 쓰기도 하지만, 대부분 대화 내용을 Claude API로 보내고 git log는 보지 않아요.
  - 30일이 지나면 세션 기록이 자동으로 지워져서, 지난달 일은 기억과 커밋 메시지에만 기대요.

## 2. 해결할 문제

- 문제:
  1. 하루의 작업이 세션 기록(무엇을 묻고 시켰나)과 여러 저장소의 커밋(실제로 무엇이 바뀌었나)에 흩어져 있어서, 날짜·프로젝트별로 한눈에 정리하기 어려워요.
  2. 세션 기록은 암호화되지 않고, 명령 출력에 나온 API 키·토큰이 그대로 남아요. 기록을 일지로 옮기거나 남에게 보여 주면 비밀 값이 함께 새어 나갈 수 있어요.
  3. 기본 설정(`cleanupPeriodDays` 30일)에서는 오래된 세션 기록이 자동으로 지워져서, 한 달 전 작업을 되짚을 재료가 사라져요. 언제 지워지는지도 사용자 눈에 보이지 않아요.
- 지금 방식으로 부족한 점:
  - 세션 뷰어(claude-code-log, claude-code-transcripts, SpecStory, cc2md)는 세션을 하나씩 보여 줄 뿐, 날짜별 일지·git 결합·비밀 가리기가 없어요.
  - git-standup은 커밋만, ccusage는 토큰 사용량만 다뤄요.
  - AI 일지 도구는 10개가 넘지만, 거의 다 대화 내용을 Claude API로 보내고 git log를 보지 않으며 비밀 값을 가리지 않아요.
  - 세션과 커밋을 함께 보는 도구도 현재 폴더 하나만(gadaj), 기록 속에 찍힌 커밋 출력만(mccm today), 기간 집계만(receipts), 커밋 단위만(Entire) 다뤄요.
  - 비밀 가리기(Entire, Confab 등)는 기록을 올리거나 넘기기 직전 단계에만 있고, 일지 도구에는 없어요.
  - Claude Code 공식 기능도 `/export`(세션 하나), `/recap`(지금 세션 한 줄), `/insights`(일하는 방식 분석)뿐이고, 일일 보고서 요청(#29585)은 2026-03에 "not planned"로 닫혔어요.
  - 정리하면, **여러 저장소의 실제 git log와 세션 기록을 날짜·프로젝트별로 맞추고, 읽는 즉시 비밀 값을 가리고, 지워지기 전에 보관하는 일을 AI 없이 내 컴퓨터 안에서 한 번에 해 주는 도구**는 2026-10-19 조사에서 찾지 못했어요. "비슷한 도구가 이미 있는데 왜 만들었나"에 대한 답이 이 빈자리예요. 그래서 이미 잘하는 도구가 있는 기능(대화 뷰어, 사용량)은 일부러 만들지 않아요. AI 요약도 기본으로는 쓰지 않고, 사용자가 켤 때만 세션마다 작업 내용 한 줄을 더하는 선택 기능으로 둬요(A24, 사용자 결정 2026-10-22).

## 3. 핵심 기능 (최대 3개)

| ID | 기능 | 설명 | 완료 기준 |
|---|---|---|---|
| F1 | 날짜·프로젝트별 작업일지 | 세션 기록과 여러 저장소의 `git log`를 읽어, 하루 단위로 프로젝트마다 세션(제목, 첫·마지막 요청, 시작~끝 시각, 사용 시간, 추가·삭제 줄 수)과 그 저장소의 실제 커밋(시각, 브랜치, 메시지 첫 줄)을 나란히 묶어요. 여러 날에 걸친 세션의 사용 시간·줄 수는 세션 전체 값이라 "(세션 전체)"를 붙이고, 사용 시간 값이 없으면 "약 N분(추정)"으로 보여 줘요(A5). 커밋은 작성 시각으로 날짜를 나눠요(A3). 세션의 작업 폴더가 저장소 하위 폴더나 워크트리여도 같은 프로젝트로 묶고, 그 폴더가 이미 지워졌어도 `--root` 없이 원래 저장소를 찾아(다른 날짜를 포함한 세션 기록 전체에서 나온 저장소, 지정한 상위 폴더 아래 저장소 중에서) 그 저장소로 묶어요(A4). 사용자가 지정한 상위 폴더 아래 저장소는 세션이 없던 날의 커밋도 넣어요. 기본 요약은 규칙 기반이라 AI도 네트워크도 쓰지 않아요. 요약 옵션(`--summary`, 기본 꺼짐, A24)을 켜면 세션마다 그날 작업 내용을 AI가 1~2문장으로 쓴 한 줄을 AI가 쓴 글이라는 표시와 함께 더해요. 이때만 사용자의 Claude Code(`claude -p`, 사용자 로그인 그대로, API 키를 따로 받지 않음)를 실행하고, F2로 가린 보관본에서 그 세션의 그날 요청·답변 글만 보내요(A25, A26). 요약을 켜면 이번 실행이 쓰는 모든 일지(기본 실행이 새로 만드는 지난 날짜 포함)를 요약하되, 실행마다 `claude`는 50번까지 최근 날짜의 세션부터 부르고 남은 세션은 다음에 요약을 켠 실행이 이어서 채워요(A24, Q26 답). 세션에 그날 새 줄이 없으면 저장해 둔 요약을 다시 쓰고(A27), 부르기에 실패해도 그 세션의 요약 줄만 비우고 일지는 만들어요(A28). 결과는 날짜마다 마크다운 파일 하나로 저장하고(세션도 커밋도 없는 날은 만들지 않아요) 로컬 화면(S1, S2)에서 봐요. 여러 날을 한 번에 만들 수 있어요(A18). 날짜 옵션 없이 실행하면 오늘 일지와 함께, 재료(보관본의 세션, `--root`·`roots` 저장소의 커밋)는 있는데 일지가 없는 지난 날짜와 그날이 끝나기 전에 만든 지난 일지를 모두 만들어요(Q25 답, 사용자 확인 2026-10-21). 요약을 켠 실행이면 요약이 빈 세션이 남은 지난 요약 일지도 다시 만들어 이어서 채워요(A18 ③). `--from`(·`--to`)으로 기간을 주면 그 안에서 재료가 있는 날짜를 모두 (이미 있어도) 다시 만들어요. 이미 있는 일지를 다시 만들 때 손으로 고친 일지 마크다운은 어느 방식에서도 덮어쓰지 않고 건너뛰어 S3에 알려요(A21). | 가짜 세션 기록과 저장소 3개로 날짜를 지정해 실행하면 네트워크 없이 그날 일지가 만들어지고, 프로젝트별 커밋 목록이 각 저장소의 `git log`(같은 작성자, 작성 시각(author date)이 그날 범위(A2 하루 경계 기준) 안인 커밋)와 개수·해시가 일치해요. 커밋 없는 세션과 세션 없는 커밋도 빠지지 않고, 작업 폴더를 지운 워크트리의 세션은 원래 저장소에서 남긴 다른 세션이 기록에 있으면(다른 날짜여도) `--root`(설정의 `roots` 포함) 없이도 원래 저장소로 묶이고(A4), `custom-title` 없이 `ai-title`만 있는 세션도 제목이 빠지지 않으며(A5), 모르는 줄 종류가 섞여 있어도 멈추지 않고 건너뛴 줄 수를 알려 줘요. 여러 날에 걸친 가짜 기록(원본을 지운 보관본만 있는 날짜, `--root` 저장소의 커밋만 있는 날짜 포함)으로 날짜 옵션 없이 실행하면(Q25 답, 사용자 확인 2026-10-21) 가장 이른 세션 날짜부터 오늘까지 재료가 있는데 일지가 없던 날짜가 모두 만들어지고, 날짜마다 같은 설정으로 그 날짜를 `--date`로 따로 만든 일지와 내용이 같아요(만든 시각 제외). 그날이 끝난 뒤 만든 일지는 바뀌지 않아요(요약을 켠 실행이 요약이 빈 세션을 이어서 채우는 요약 일지만 예외, A18 ③). `--from`·`--to`로 준 기간은 재료가 있는 날짜가 모두 다시 만들어지고, 어느 방식이든 손으로 고친 일지 마크다운이 있는 날짜는 마크다운과 화면용 일지 데이터가 둘 다 그대로이며 S3에 그 날짜가 나와요(A21). 요약 옵션을 켜지 않으면(기본, `config.json` 포함) 어느 실행 방식에서도 `claude` 실행이 0회이고 네트워크 요청이 0건이에요(A24). `claude` 실행 파일을 가짜로 바꿔(A26) `--summary`로 실행하면, 요약을 켠 일지의 세션마다 가짜가 돌려준 요약이 AI 글 표시와 함께 한 줄로 마크다운과 화면용 일지 데이터에 들어가요. 가짜가 받은 것은 표준 입력으로 넘긴 그 세션 그날의 가린 제목·요청·답변 글뿐이고(비밀 값 원문·도구 출력·첨부·도구 호출 입력·서브 에이전트 대화·커밋 메시지·다른 날 줄 없음, 길이 상한 이하, A25), 받은 인자에는 A26 조건(도구 없음, 사용자 설정·MCP·훅 끼어들지 않음, 세션 기록 남기지 않음)을 지키는 옵션이 빠지지 않아요. 세션에 그날 새 줄이 없으면 다시 실행해도 `claude`를 부르지 않고 같은 요약이 들어가며, 한 세션에 줄이 늘면 그 세션만 다시 불러요(A27). 가짜가 실행 파일 없음·로그인 안 됨·시간 초과·사용량 제한을 흉내 내면 일지는 그 세션의 요약 줄 없이 만들어지고 종료 코드는 그대로이며 S3에 이유별 수가 나와요(A28). 손으로 고친 일지의 날짜는 부르지 않아요(A21). 부를 세션이 50개보다 많은 여러 날 가짜 기록으로 `--summary` 기본 실행을 하면 지난 날짜도 요약을 켠 일지로 만들어지고, 가짜 `claude`는 50번만 실행되며 날짜가 늦은 세션부터 불리고, S3에 요약이 빈 채 남은 세션 수가 나와요. 다시 `--summary`로 기본 실행하면 이미 받은 요약은 부르지 않고 남은 세션을 같은 순서로 이어서 불러(그날이 끝난 뒤 만든 일지여도) 실행을 거듭하면 모두 채워지고, `--from`과 함께 켜도 같은 상한과 순서예요(A24). |
| F2 | 읽는 즉시 비밀 값 가리기 + 검사 | 세션 기록과 커밋 메시지를 읽는 단계에서, 일지·보관본·화면 어디에든 쓰기 전에 알려진 비밀 값 형식(클라우드·AI 서비스·GitHub·npm·Slack 등의 키와 토큰, 개인 키 블록, JWT, 접속 주소 속 비밀번호, 이름에 KEY·SECRET·TOKEN·PASSWORD 등이 든 `이름=값` 줄)을 정해진 규칙으로 찾아 종류 표시로 바꿔요. 가리기 전 원문은 디스크에 남기지 않아요. 원문(세션 대화·커밋 메시지)에 가림 표시와 같은 모양의 글자가 들어 있으면 도구가 가린 자리와 구분되게 남기고, 검사·다시 가리기·화면에서 가린 자리로 세거나 표시하지 않아요(A17). 사용자는 자기 패턴을 더할 수 있고, 패턴마다 시험 값을 함께 적을 수 있어요(선택). 일지를 공개할 때를 위한 옵션을 켜면 경로 속 사용자 이름(`C:\Users\이름`, `/home/이름` 등)과 이메일 주소도 일지(마크다운·화면)에서 가려요. 이 옵션은 기본으로 꺼져 있고 보관본에는 적용하지 않아요(A10). 요약 옵션(A24)으로 받은 AI 요약도 받는 즉시 같은 규칙으로 가린 뒤에만 요약 저장 파일에 두고(가리기 전 요약 글은 디스크에 남기지 않아요), 일지에 넣을 때 지금 규칙으로 한 번 더 가리며 이름·이메일 가리기(켰을 때)도 적용해요. 요약 글 속 가림 표시 모양 글자도 도구가 가린 자리로 세지 않아요(A27). 검사 명령은 ① 내장된 가짜 비밀 값 모음과 사용자 패턴의 시험 값으로 패턴마다 잡히는지 시험하고 ② 데이터 폴더의 결과물(일지·화면용 일지 데이터·보관본·보관 색인·요약 저장 파일, 일지의 요약 줄 포함)을 지금 규칙으로 다시 훑어 남은 의심 문자열을 센 뒤, S4 기준으로 통과·실패를 정해요. 이름·이메일 가리기를 끄고 만든 일지에 남은 사용자 이름·이메일도 값 없이 세어 `[알림]`으로 알리지만, 통과·실패에는 넣지 않아요(A19). 남은 이름·이메일의 수는 켠 일지든 끈 일지든 일지 마크다운에서 찾은 자리로 세요(A23). 보관은 늘어난 부분만 더해서 나중에 더한 패턴이 이미 보관한 줄에는 닿지 않아요. 그래서 보관본 다시 가리기로 보관본에 이미 들어간 값을 지금 규칙(내장 규칙 + 사용자 패턴)으로 다시 가려요(요약 저장 파일도 보관본과 같은 규칙으로 다시 가려요, A27). 원본이 지워진 보관본에도 동작하고, 그 보관본으로 만든 명령에서만 받아요. 날짜·시각·해시·세션 아이디·하루 경계 칸과 보관 색인은 다시 가리지 않고, 그런 칸이나 읽을 수 없는 줄·손으로 고친 줄에 걸려 고칠 수 없는 의심은 `[알림]`으로 알린 뒤 검사가 계속 위치를 보여 줘요(A16, S3). | 가짜 비밀 값 10종 이상이 든 시험 기록으로 일지와 보관본을 만들면 데이터 폴더 어디에도 원문이 없고, 검사 끄면(기본) 그대로 남아요. 끄고 만든 일지에 경로 속 사용자 이름이나 이메일이 남아 있으면 검사는 그 수(값 없이)와 `--hide-identity`로 다시 만들라는 `[알림]`을 보여 주고, 판정과 종료 코드는 그 수와 상관없이 같아요(A19). 남은 사용자 이름·이메일 수는 일지 마크다운의 자리라서, 이메일 하나가 든 요청 하나로 만든 일지는 끈 가리기를 실행하면 보관본과 이미 만든 일지(마크다운·화면용 일지 데이터)에서 그 값이 사라지고 검사가 통과해요. 다시 가리기는 다시 쓰기 전에 바뀔 보관본·일지 파일마다 바뀔 자리 합계와 전체 종류별 합계(사용자 패턴은 패턴별)를 값 없이 보여 주고, 확인을 거절하거나 확인을 물을 수 없는 환경에서 `--yes` 없이 실행하면 데이터 폴더의 어떤 파일도 바뀌거나 새로 생기지 않아요(종료 코드 1). 확인하거나 `--yes`를 줬을 때만 다시 쓰고, 파일마다 실제로 바뀐 자리 수는 먼저 보여 준 수와 같아요. 다시 가리기가 읽거나 쓰지 못한 보관본·일지 파일이 있으면(다른 프로그램이 잡고 있음, 권한 없음 등) 그 사실과 파일 위치를 알리고 성공으로 끝내지 않으며(종료 코드 1), 같은 날짜의 일지 마크다운과 화면용 일지 데이터 중 한쪽만 가려진 채 남지 않아요. 다시 가리기를 두 번 실행해도 결과가 같고(두 번째는 바뀔 자리 0개라 묻지 않고 끝나요), 남아 있는 원본 세션 파일의 내용·수정 시각은 그대로예요. 가짜 `claude`(A26)가 가짜 비밀 값·이메일·경로 속 사용자 이름·가림 표시 모양 글자가 든 요약을 돌려주면, 일지(마크다운·화면용   - 핵심 기능은 3개까지라, 넣을 때 F1의 재료를 넓히는 것으로 볼지는 기획에서 다시 정해요.

## 4. 화면 목록

| ID | 화면 | 목적 | 관련 기능 |
|---|---|---|---|
| S1 | 날짜 목록 (로컬 화면) | 일지가 있는 날짜를 훑고 하루를 고르는 화면이에요. 날짜마다 프로젝트 수·세션 수·커밋 수와 보관 상태를 보여 줘요. 보관 상태는 5가지(보관됨 · 보관 실패 · 삭제 임박 D-n · 보관본만 남음 · 세션 없음(커밋만 있는 날))예요. 한 날짜에 상태가 섞이면 "삭제 임박 > 보관 실패 > 보관됨 > 보관본만 남음" 순서로 가장 급한 것 하나와 그 개수를 보여 줘요. 화면은 원본을 열지 않아서 상태는 모두 마지막 실행 기준이고, 그 기준 시각을 함께 보여 줘요. "보관 실패"(삭제 예상일까지 8일 이상)와 "삭제 임박"(7일 이하)은 마지막 실행에서 그 세션 보관에 실패했을 때만 나와요(F3, A9). 일지가 없는 날짜(보관만 했거나 그날 일지를 만들지 않은 날)의 보관 실패 세션처럼 날짜 행에 잡히지 않는 실패 세션도 알 수 있어야 해서, 보관 실패를 알리는 배너에 링크 없이 "일지가 없는 날짜의 보관 실패 세션 N개도 있어요" 같은 한 줄로 보여 줘요(삭제 임박 포함, 일지가 하나도 없어도 보여요). 보관본 다시 가리기가 파일을 바꾸기 시작한 뒤에 멈춰 다시 쓰기 기록이 남아 있으면 S4 `[알림]`과 같은 뜻을 화면에도 알려요. 다시 쓰기 기록이 깨져 읽을 수 없을 때도 S4처럼 일부만 바뀌었을 수 있다고 보고, "다시 쓰기 기록이 깨져 자동으로 마저 끝낼 수 없어요"와 `cc-worklog redact`를 다시 실행하라는 안내로 알려요. 깨진 기록에서 시작한 다시 가리기가 확인 뒤 확정 전에 멈추거나 되돌려진 때도 같아요(A16, 사용자 확인 2026-10-20). 화면은 마저 끝내지 않아요(A16). | F1, F3 |
| S2 | 하루 일지 (로컬 화면) | 고른 날짜의 일지를 프로젝트별로 읽는 화면이에요. 프로젝트마다 세션과 커밋을 시간순으로 함께 보여 주고, 가려진 자리는 종류와 함께 표시해요. 같은 내용의 마크다운 파일 위치도 알려 줘요. 프로젝트 목차(같은 화면 안 이동)와 이전·다음 날짜(일지가 있는 날짜끼리) 이동, 그날의 보관 상태(S1과 같은 규칙)도 있어요. "보관 실패"·"삭제 임박"은 S1처럼 마지막 실행에서 보관에 실패했을 때만 나와요. 다시 가리기가 멈춘 채 남은 상태도 S1처럼 알려요(다시 쓰기 기록이 깨진 경우와, 깨진 기록에서 시작한 다시 가리기가 확인 뒤 확정 전에 멈추거나 되돌려진 경우 포함, A16, 사용자 확인 2026-10-20). 요약을 켜고 만든 일지면 세션마다 AI가 쓴 작업 내용 한 줄을 AI가 쓴 글이라는 표시와 함께 보여 주고, 요약을 켰다는 것과 요약한 세션 수도 보여 줘요(A24). 요약 글은 요청 글처럼 글자 그대로 보여 주고 가린 자리는 다른 글처럼 표시해요. 화면은 요약을 부르지 않고 일지에 저장된 글만 보여 줘요. 이름·자리·모양은 디자인이 정해요. | F1, F2 |
| S3 | 실행 요약 (터미널) | 일지 만들기·보관 명령(보관본 다시 가리기 포함)이 끝난 뒤의 출력과, 보관본 다시 가리기가 다시 쓰기 전에 확인을 묻는 출력이에요. 읽은 세션·커밋 수(보관만 실행했으면 세션·파일·새로 읽은 줄 수), 새로 보관한 세션 수, 종류별 가린 개수와 이름·이메일 가리기 옵션이 켜졌는지, 건너뛴 줄 수와 기록 형식 버전, 삭제 임박 안내, 결과 파일 위치와 화면 여는 법을 담아요. 일지 만들기가 여러 날짜를 만들면(A18) 날짜마다 늘어놓지 않고, 만든 날짜 범위와 날짜 수(새로 만듦·다시 만듦, 기본 실행이면 그대로 둔 날짜 수도), 읽은 세션·커밋 수와 가린 개수의 합계, 일지 폴더 위치를 한 번만 보여 줘요. 기간이 길어도 출력이 날짜 수만큼 길어지지 않게 하려는 거예요. 날짜를 하나만 만들었으면 지금처럼 그 일지 위치를 보여 주고, 새로 만들었는지 이미 있던 일지를 다시 만들었는지 알려요(A21). 만들 날짜가 하나도 없으면 만든 일지가 없다고 알려요. 손으로 고쳐 건너뛴 일지는 날짜를 줄이지 않고 모두 `[알림]`으로 보여 주고, 메모를 다른 곳에 옮긴 뒤 그 `.md` 파일을 옮기거나 지우고 다시 실행하면 새로 만들어진다고 안내해요(종료 코드 그대로, A21). `--date`·`--from`으로 이미 있는 일지를 다시 만들면서 이름·이메일 가리기가 켜져 있던 일지를 끈 채로 만들었으면, 그 날짜를 모두 `[알림]`으로 알리고 `--hide-identity`를 붙여 다시 만드는 법을 보여 줘요(A21). 요약 옵션을 켠 일지 만들기면(A24) 요약한 세션 수(새로 부름 · 저장해 둔 요약 다시 씀)와 요약하지 못한 세션 수를 이유별로(0인 이유는 빼요) 보여 주고, 못 한 세션이 있으면 `[알림]`으로 이유마다 할 일을 알려요(종료 코드 그대로, A28). 보낸 세션(A28의 뜻: `claude`를 실행한 세션 중 보내기 전에 멈춘 것이 확실한 세션만 뺀 수)이 있으면 가린 대화 글을 Claude Code로 Anthropic에 보냈고 Claude Code 사용량을 썼다는 것을 그 세션 수와 함께 한 줄로 알려요. 성공한 세션만이 아니라 실패했어도 재료가 나갔을 수 있는 세션도 세요(취합 20회차 차이 3, 사용자 결정 2026-10-23). 여러 날짜를 만들어도 합계로 한 번만이에요. 받은 요약을 요약 저장 파일에 쓰지 못했으면 멈추지 않고 `[알림]`으로 알려요(종료 코드 그대로, A27). 이번 실행 뒤에도 요약이 빈 채 남은 세션이 있으면 그 세션 수와 그 일지(날짜) 수, 상한(실행마다 `claude` 50번)에 닿았는지(50번을 다 실행했고 이번에 부르지 못한 세션이 남았는지, A24), 다음에 요약을 켜고 실행하면 최근 날짜부터 이어서 채운다는 것을 한 줄로 알려요(A24, Q26 답). 요약을 부르는 중 Ctrl+C로 끊으면 결과 요약 대신 표준 오류에 `[취소]` 안내(받은 요약이 있으면 저장해 뒀다는 것, 요약을 켜고 다시 실행하면 빠진 세션만 이어서 부른다는 것)만 보여 주고 `화면`·`검사` 줄은 없어요. 그 실행은 일지를 하나도 쓰지 않고 종료 코드는 1이에요(A26, DESIGN 제안 20, 취합 20회차 차이 4, 사용자 결정 2026-10-23). 요약을 켜고 만든 일지를 끈 채 다시 만들어 요약 줄이 빠진 날짜도 수와 `--summary`로 다시 만드는 법을 한 줄로 알려요(A28). 요약을 끈 기본 실행도 요약이 빈 채 남은 요약 일지가 있으면(요약을 끈 실행이 다시 만든 요약 일지에서 비운 세션 포함) 그 세션 수와 `--summary`로 실행하면 이어서 채운다는 것을 한 줄로 알려요(A28). 요약을 끈 실행에서는 요약한 세션 수와 보냈다는 줄이 없고(기본 S3 그대로), 요약 줄이 빠진 날짜·세션 안내만 나올 수 있어요. 일지 만들기에 `--root`도 `config.json`의 `roots`도 없으면, 세션이 있던 저장소의 커밋만 읽었다는 것과 세션 없이 커밋한 저장소는 `--root`나 `roots`로 알려 주면 들어간다는 안내 한 줄을 넣어요. 경고가 아니라 안내라서 `[경고]`로 보이지 않게 하고(모양은 디자인이 정해요), 여러 날짜를 만들어도 한 번만 넣으며, git을 찾지 못해 커밋을 읽지 않았을 때는 빼요(A20). 건너뛴 줄 수는 모르는 줄 종류, 읽을 수 없는 줄, 꼭 필요한 값(`timestamp`·`cwd`·`sessionId`)이 없어 버린 요청·답변 줄을 합쳐 세고, 이유별로 나눠 보여 줘요(0인 이유는 빼요). 2026-10-20 실제 기록에서 처음 본 줄 종류 12가지는 아는 줄이라 세지 않아요(A13). 기록 형식은 여러 버전이 섞이는 것이 정상이라, 기준보다 새 버전이 있을 때만 `[알림]`으로 그중 가장 새 버전을 보여 주고, 옛 버전은 `[알림]` 없이 "옛 형식 파일 N개"로 파일 수만 알려요(A13, 사용자 확인 2026-10-20). 삭제 임박은 보관 전 기준으로 "삭제 예상일이 7일 안이던 세션 N개를 이번에 보관했어요"처럼 알리고, `[경고]`는 보관에 실패해 여전히 삭제 위험이 있는 세션이 있을 때만 띄워요(F3). 세션 기록 폴더가 없으면 멈추지 않고 `[알림]`을 띄운 뒤 커밋만으로 일지를 만들고, 세션도 커밋도 없는 날이면 만든 일지가 없다고 알려요. `--root`(또는 `config.json`의 `roots`)에 준 경로가 없거나, 폴더가 아닌 파일이거나, 그 아래에서 git 저장소를 하나도 찾지 못하면, 멈추지 않고(종료 코드 그대로) 나머지 일을 끝낸 뒤 그 경로를 건너뛰었다는 `[알림]`을 경로마다(세 경우 중 어느 것인지 함께) 보여 줘요(A4). 다시 가리기는 먼저 바뀔 보관본·일지 파일(요약 저장 파일 포함, A27)마다 바뀔 자리 합계를 줄이지 않고 모두 보여 주고, 전체 바뀔 자리를 종류별로 합쳐(사용자 패턴은 패턴별) 보여 준 뒤 확인을 물어요. 값은 보여 주지 않고, 원본이 지워져 되돌릴 수 없는 보관본은 표시해요. 다시 가리기로 고칠 수 없는 의심이 있으면 그 수를 `[알림]`으로 알려요(A16). 그중 일지 마크다운과 화면용 일지 데이터 중 한쪽만 가려진 일지에 걸린 것은 그 날짜와, 그 날짜 일지를 다시 만들면 고쳐진다는 안내를 다시 만드는 명령과 함께 보여 줘요(A16). 이 명령은 그 일지를 만든 설정과 같게 다시 만드는 명령이에요. `cc-worklog --date <날짜>`에, 그 일지를 이름·이메일 가리기를 켜고 만들었으면 `--hide-identity`, 요약을 켜고 만들었으면 `--summary`(A28), 그 일지의 하루 경계가 기본(새벽 3시, A2)이나 지금 설정(`config.json`의 `dayStartHour` 또는 이번 실행의 `--day-start`)과 다르면 `--day-start N`(N은 그 일지의 하루 경계, 둘 다 같으면 붙이지 않아요), 이번 실행에 `--data-dir`로 데이터 폴더를 줬으면 `--data-dir <폴더>`, `--claude-dir`로 세션 기록 폴더를 줬으면 `--claude-dir <폴더>`를 붙여요(`--day-start` 조건과 `--claude-dir`는 Q22·Q23 답, 사용자 확인 2026-10-21). 옵션으로만 준 `--root`와, 만들 때 줬지만 이번 실행에는 주지 않은 `--claude-dir`는 일지에 남지 않아 붙일 수 없어서, "만들 때 `--root`나 `--claude-dir`를 줬으면 같은 값을 붙이세요" 한 줄을 더해요. 세션 기록 폴더 경로는 사용자 이름이 들어가서 일지에 남기지 않아요(A10). 이번 실행에 `--claude-dir`를 줬으면 명령에 붙이는 것은 위와 같아요(A16, 취합 13회차 차이 1, 사용자 확인 2026-10-20, `--claude-dir`를 합친 한 줄은 Q24 답, 사용자 확인 2026-10-21). 다시 가리기가 읽거나 쓰지 못한 보관본·일지 파일(다른 프로그램이 잡고 있음, 권한 없음 등)이 있으면 말없이 건너뛰지 않고 그 파일 위치(원인 코드도 함께)를 모두 보여 주며, `[실패]`로 알리고 종료 코드 1로 끝내요. "다시 씀"만 보여 주고 성공처럼 끝내지 않아요(A16). 지난번 다시 가리기의 다시 쓰기 기록이 깨져 읽을 수 없으면, 일지 만들기·보관은 하던 일을 그대로 끝내고 "다시 쓰기 기록이 깨져 자동으로 마저 끝낼 수 없어요"라는 `[알림]`과 `cc-worklog redact`를 다시 실행하라는 안내를 더해요(종료 코드는 그대로예요). 다시 가리기는 같은 `[알림]`과 함께 이번 실행이 지금 파일로 바뀔 자리를 다시 셌다고 알리고, 거절했거나 확인을 물을 수 없어 멈췄으면 `cc-worklog redact`를 다시 실행하라고 안내하며, 바뀔 자리가 0개면 묻지 않고 깨진 기록을 정리했다고 알려요(A16). 확인한 뒤 확정 전에 멈추거나 되돌려지면 "깨짐" 표시를 다시 남겨서, 다음 일지 만들기·보관·다시 가리기도 같은 `[알림]`과 `cc-worklog redact` 다시 실행 안내를 보여 줘요. 그 자리의 `[실패]` 문구는 보통 때와 같아요(A16, 사용자 확인 2026-10-20). `y`·`yes`·`예`·`네`만 확인이고, 그냥 Enter와 그 밖의 답은 거절이에요. 확인하면(`--yes`를 줬으면 묻지 않고) 다시 쓴 보관본·일지 수와 새로 가린 개수를 보여 줘요. 거절하면 바뀐 파일이 없다고 알리고, 확인을 물을 수 없는 환경에서 `--yes` 없이 실행했으면 바뀔 자리 수와 함께 바뀐 파일이 없다는 것과 `--yes`를 붙여 다시 실행하는 법을 알려요(두 경우 모두 종료 코드 1). 바뀔 자리가 0개면 묻지 않고 바뀐 파일이 없다고 알려요(종료 코드 0). 끝에 "공개 전에 `cc-worklog check`로 확인하세요" 한 줄을 넣어요. 이번 일지 만들기가 이름·이메일 가리기를 끈 채로 만든(다시 만든 것 포함) 일지가 있으면, 이 줄에 그 일지는 이름·이메일을 가리지 않았고 공개하려면 `--hide-identity`로 만들라는 말을 더해요. 검사는 이름·이메일을 판정에 넣지 않아서, 검사 통과만 보고 공유하지 않게 하려는 거예요(A19). 보관·다시 가리기의 이 줄은 그대로예요. 다만 다시 가리기를 거절했거나 질문 중 Ctrl+C로 끊었거나 확인을 물을 수 없어 멈췄을 때(종료 코드 1), 일지 만들기가 AI 요약을 부르는 중 Ctrl+C로 끊었을 때(종료 코드 1, A26), `[실패]`로 끝날 때는 이 줄을 넣지 않고 그 경우의 안내만 보여 줘요. 데이터 폴더에 쓰지 못해 `[실패]`로 끝날 때는 첫 줄 끝에 원인 코드(`EACCES`, `ENOSPC` 등, 파일 내용이 아니에요)를 괄호로 붙이고, `다음:` 줄은 `다음: 폴더 권한과 디스크 공간을 확인하거나 --data-dir로 다른 폴더를 고르세요.`로 해요. 권한 문제와 디스크 가득 참은 할 일이 달라서예요(취합 8회차 차이 2, 사용자 확인 2026-10-20). | F1, F2, F3 |
| S4 | 가리기 검사 결과 (터미널) | 검사 명령의 출력이에요. 패턴별 시험 결과(내장 가짜 값은 잡힘 / 놓침, 사용자 패턴은 시험 값이 있으면 잡힘 / 놓침, 없으면 "시험 값 없음"), 결과물을 지금 규칙(내장 규칙 + 사용자 패턴)으로 다시 훑어 남은 의심 문자열 수(값은 보여 주지 않고 파일·줄 위치만), 최종 통과·실패를 보여 줘요. 통과는 내장 가짜 값이 모두 잡히고, 가리면 안 되는 값(커밋 해시·파일 경로·일반 문장 등)이 그대로이고, 시험 값이 있는 사용자 패턴이 모두 잡히고, 남은 의심이 0건이고, 이름·이메일 옵션이 켜진 일지가 있으면 그 일지에 남은 사용자 이름·이메일도 0건일 때만이에요. 종료 코드는 통과 0 / 실패 1이에요. 판정에 드는 남은 이름·이메일 수는 옵션이 켜진 일지만 세요(보관본은 이 옵션을 쓰지 않아서 세지 않아요). 옵션이 꺼진 일지에 남은 사용자 이름·이메일도 값 없이 세어 보여 주지만 판정에는 넣지 않아요. 켠 일지·끈 일지 모두 남은 이름·이메일의 "건"은 일지 마크다운에서 찾은 자리예요. 화면용 일지 데이터도 훑지만 마크다운과 같은 내용이라 수에 더하지 않고, 같은 날짜 마크다운에 없는 종류(사용자 이름 / 이메일)가 화면용 일지 데이터에만 남아 있으면 그 파일을 그 종류 1건으로 세어 판정·`[알림]`에서 빠지지 않게 해요. 켠 일지의 위치 목록도 수에 든 자리만 보여 줘요. 남은 의심(비밀 값) 수는 지금처럼 결과물 파일마다(일지 마크다운·화면용 일지 데이터·보관본·보관 색인·요약 저장 파일) 찾은 자리를 더해요(A23, 사용자 위임 2026-10-22). 일지의 AI 요약 줄은 일지의 일부로 다른 글과 똑같이 검사하고(남은 의심, 켠 일지·끈 일지의 남은 이름·이메일), 요약 저장 파일은 보관본처럼 이름·이메일 가리기를 쓰지 않는 재료라 남은 이름·이메일은 세지 않아요(A27). "옵션이 꺼져 있어 세지 않았어요"만 보여 주지 않고 실제 수를 보여 주고, 하나라도 있으면 판정 줄 가까이에 `[알림]`으로 옵션을 끈 일지 수와 남은 사용자 이름·이메일 수, `[통과]`는 비밀 값 기준이라 그 일지의 이름·이메일은 그대로라는 것, 공개할 날짜의 일지는 `--hide-identity`로 다시 만들라는 안내를 보여 줘요. 옵션을 끈 일지는 대개 전부라서 파일·줄 위치나 날짜마다의 명령은 늘어놓지 않아요(날짜 목록을 보여 줄지, 명령 모양을 보여 줄지는 디자인이 정하되, 명령을 보여 주면 이번 실행에 준 `--data-dir`·`--claude-dir`는 빠지지 않아야 해요, A16). 통과·실패 기준과 종료 코드는 그대로예요(A19). 남은 의심이 있으면 (필요하면 사용자 패턴을 더한 뒤) 보관본 다시 가리기(F2)를 실행하고 다시 검사하라고 안내해요. 다만 검사가 읽지 못한 일지·보관본·보관 색인·요약 저장 파일·폴더를 남은 의심으로 셀 때는 일반 비밀 값 의심과 구분해 "읽지 못함"과 원인 코드를 보여 주고, 그때의 `다음:`은 다시 가리기가 아니라 그 파일을 연 프로그램을 닫거나 권한을 확인한 뒤 다시 검사하라는 안내예요(읽지 못한 파일이 있으면 실패인 것은 그대로예요, 취합 13회차 차이 5, 사용자 확인 2026-10-20). 요약 저장 파일은 열리지만 내용이 깨진 파일(JSON이 아니거나 요약 저장 파일 모양이 아님)도 읽지 못한 파일로 세고(원인 코드 대신 깨졌다는 표시), 그때의 `다음:`은 다시 가리기가 아니라 그 파일을 지워도 일지는 그대로이고 요약을 켜고 그 날짜를 다시 만들면 다시 부른다는 안내예요. 표시와 문구는 디자인이 정해요(A27, 취합 20회차 차이 7, 사용자 결정 2026-10-23). 읽지 못한 파일·폴더는 하나를 한 건으로 세고, 읽다 중간에 멈춘 파일은 그 파일에서 앞서 찾은 의심(남은 이름·이메일 포함)을 따로 세지 않아요. 다시 검사하면 다시 나오고, 이래야 남은 의심 수와 목록이 맞아요(취합 15회차 차이 2, 사용자 확인 2026-10-21). 남은 의심이 일지 마크다운과 화면용 일지 데이터 중 한쪽만 가려진 일지에 있으면, 다시 가리기로 고쳐지지 않을 수 있어서 그 날짜와, 그 날짜 일지를 다시 만들면 고쳐진다는 안내도 다시 만드는 명령과 함께 보여 줘요. 명령은 S3와 같은 규칙으로 그 일지를 만든 설정과 같게 다시 만드는 명령이고(`--hide-identity`, 요약을 켜고 만든 일지의 `--summary`(A28), 하루 경계가 기본이나 지금 설정과 다를 때의 `--day-start N`, `--data-dir <폴더>`, `--claude-dir <폴더>`), "만들 때 `--root`나 `--claude-dir`를 줬으면 같은 값을 붙이세요" 한 줄도 같아요(A16, 사용자 확인 2026-10-20, `--day-start` 조건과 `--claude-dir`는 Q22·Q23 답, 한 줄로 합친 것은 Q24 답, 사용자 확인 2026-10-21). 이름·이메일 옵션이 켜진 일지에 남은 사용자 이름·이메일이 있을 때의 `다음:` 안내도, 그 날짜마다 같은 규칙의 다시 만드는 명령과 같은 안내 한 줄을 보여 줘요. 옵션이 켜진 일지의 이름·이메일을 가리려고 다시 만드는 것이라 이때는 `--hide-identity`가 늘 붙고, 나머지(`--summary`, `--day-start N`, `--data-dir <폴더>`, `--claude-dir <폴더>`)는 위와 같아요. 같은 날짜가 두 안내에 다 걸릴 때 어떻게 보일지는 디자인이 정해요(A10, A16, DESIGN 제안 19, 취합 15회차 차이 1, 사용자 확인 2026-10-21). 놓칠 수 있는 것(형식 없는 비밀, 문장 속 이름, 요약을 켰다면 AI가 규칙이 놓친 값을 다른 모양으로 바꿔 쓴 것, A27)도 한 줄로 알려 줘요. 보관본 다시 가리기가 파일을 바꾸기 시작한 뒤에 멈춰 다시 쓰기 기록이 남아 있으면, "지난번 다시 가리기가 끝나지 않아 일부 파일만 바뀐 상태일 수 있고, 다음 `cc-worklog`·`cc-worklog archive`·`cc-worklog redact` 실행이 마저 끝낸다"는 `[알림]`을 보여 줘요. 다시 쓰기 기록이 깨져 읽을 수 없으면 일부만 바뀌었을 수 있다고 보고, 이 안내 대신 "다시 쓰기 기록이 깨져 자동으로 마저 끝낼 수 없어요"라는 `[알림]`과 `cc-worklog redact`를 다시 실행하라는 안내를 보여 줘요. 깨진 기록에서 시작한 다시 가리기가 확인 뒤 확정 전에 멈추거나 되돌려진 때도 같아요(A16, 사용자 확인 2026-10-20). 검사는 읽기만 해서 마저 끝내지 않고 지금 파일을 그대로 검사하며, 통과·실패 기준과 종료 코드는 바꾸지 않아요(A16). | F2 |

참고: CLI 출력 중 S3와 S4만 화면으로 셌어요. 이 둘은 사용자가 결과를 읽고 판단하는 곳(보관이 됐나, 비밀 값이 남았나, 삭제가 임박했나)이고, F2 확인과 F3 경고는 로컬 화면을 열지 않으면 터미널에서만 보이기 때문이에요. 보관본 다시 가리기의 출력도 실행 요약이라 새 화면을 만들지 않고 S3에 넣었어요. 다시 쓰기 전 확인 출력도 같은 명령 안에서 결과 바로 앞에 이어지는 한 흐름(바뀔 자리 수 → 확인 → 결과)이라 S3에 함께 넣었어요. S4는 아무것도 바꾸지 않는 검사 명령의 출력이라 확인을 넣지 않았어요. 도움말·오류·버전 출력은 보통의 CLI 관례를 따르면 돼서 화면으로 세지 않았어요. 다만 옵션 오류 문구도 한국어로만 보여 줘요(A22).

## 5. 기술 메모

- 플랫폼: npm으로 설치하는 CLI + 브라우저에서 여는 읽기 전용 로컬 화면이에요. Windows·macOS·Linux에서 돌아야 하고, 사용자 환경이 Windows라 Windows 경로(`C:\Users\...\.claude\projects`)를 먼저 확인해요. 화면 열기 명령을 터미널에서 실행하면 기본 브라우저로 날짜 목록이 열려요. 요청한 포트(기본 포트 포함)가 쓰이는 중이면 다음 빈 포트로 열되, "요청한 포트 N이 쓰이는 중이라 M으로 열었어요"처럼 바뀐 사실을 터미널에 알려요(S1~S4 밖의 짧은 출력, 시나리오 실행 F1-21, 사용자 확인 2026-10-20).
- 스택 제약:
  - Node.js(LTS) + TypeScript를 써요. 로컬 화면 쪽 프레임워크는 개발 에이전트가 정하되, npm 패키지 하나에 함께 담겨 설치 뒤 네트워크 없이 열려야 해요(CDN·외부 글꼴 불러오기 금지).
  - 기본 동작에서 네트워크 요청은 0건이에요. 계정·API 키·외부 서비스 없이 돌아야 해요.
    - 예외는 요약 옵션(A24)을 켠 일지 만들기 하나예요. 이때도 이 도구는 직접 네트워크를 쓰지 않고, 사용자가 설치·로그인한 Claude Code CLI(`claude -p`)를 실행해 Claude Code가 Anthropic으로 보내요. 이 도구는 API 키를 받거나 읽거나 보여 주지 않아요. `claude`가 없거나 로그인하지 않았어도 요약 줄만 빠지고 나머지는 지금처럼 돌아요(A28). 옵션을 끄면 어느 명령에서도 `claude` 실행 0회·네트워크 요청 0건이에요.
    - 요약 호출은 A26의 조건을 지켜야 해요: 도구(파일 읽기·명령 실행 등)를 하나도 쓰지 못함, 사용자의 MCP·훅·플러그인·설정·CLAUDE.md가 끼어들지 않음, 새 세션 기록을 남기지 않음, 재료는 표준 입력으로(명령줄 인자·임시 파일 아님), 한 번에 60초, 동시에 2개까지, 실행마다 50번까지(최근 날짜부터, A24), 실패는 이유 종류만 보여 주기. 구체 플래그는 개발이 사용자 컴퓨터의 Claude Code 판(2.1.306)으로 확인해 `docs/DEV.md`에 적어요.

S1·S2에서는 마지막 실행에서 보관에 실패한 세션을 "보관 실패"(삭제 예상일까지 8일 이상) 또는 "삭제 임박"(7일 이하)으로 보여 줘요. "보관 안 됨"은 "아직 차례가 안 왔다"로 읽힐 수 있어 이름을 바꿨어요. (F3, 사용자 확인 2026-10-20, 남은 질문 Q7)
  - **A10 가리는 범위**: 형식이 알려진 비밀 값, 이름으로 알 수 있는 `이름=값` 줄, 사용자 패턴은 항상 가려요. 경로 속 사용자 이름(`C:\Users\이름`, `/home/이름`, `/Users/이름` 등)과 이메일 주소는 기본으로는 그대로 두고, 옵션을 켜면 일지(마크다운·화면)에서 종류 표시로 바꿔요. 일지를 공개할 때 쓰는 옵션이에요. (사용자 확인 2026-10-19)
    - 이 옵션은 보관본에 적용하지 않아요(사용자 답에 없어 기획에서 정했어요). 보관본은 공개하지 않는 재료이고, 보관본에서 한 번 가리면 되돌릴 수 없어서 원본이 지워진 뒤에는 옵션을 끈 일지를 다시 만들 수 없기 때문이에요. 이렇게 하면 같은 보관본으로 옵션을 켠 일지와 끈 일지를 모두 만들 수 있어요.
    - 한쪽만 가려진 일지를 다시 만들라는 안내(S3·S4)는, 그 일지를 이 옵션을 켜고 만들었으면 명령에 `--hide-identity`를 붙여 보여 줘요. 빼고 다시 만들면 공개하려던 일지에 이름·이메일이 드러나요. (A16, 취합 13회차 차이 1, 사용자 확인 2026-10-20) 검사(S4)가 이 옵션이 켜진 일지에 남은 사용자 이름·이메일을 찾았을 때 날짜마다 보여 주는 다시 만드는 명령도 같은 규칙이고, 이때는 `--hide-identity`가 늘 붙어요. (S4, A16, 취합 15회차 차이 1, 사용자 확인 2026-10-21)

  - **A11 반대 논거 — 비슷한 도구가 많아요(쓰는 사람이 적다는 신호일 수 있어요)**: 세 차별점만 만들고, 이미 있는 기능(뷰어·사용량)은 빼서 대응해요. AI 요약은 기본 꺼짐 선택 기능(세션마다 한 줄)으로만 둬서, 기본 동작의 "AI·네트워크 없이"는 그대로예요(A24, 사용자 결정 2026-10-22). 2주 포트폴리오라 사용자 수보다 "조사로 빈자리를 찾고 범위를 좁힌 판단"을 보여 주는 것이 목표라고 가정해요. README에 기존 도구와의 비교 표를 둬요.
  - **A12 반대 논거 — 공식 receipts가 넓어지면 겹쳐요**: receipts는 기간 집계 중심이라, 내 컴퓨터 안에서 비밀을 가리고 날짜별 일지를 남기고 보관하는 부분은 겹쳐도 남는다고 봐요. 공식 기능이 날짜별 일지까지 넓어지면 F1을 줄이고 F2·F3에 집중해요.
  - **A13 반대 논거 — 세션 기록 형식이 바뀔 수 있어요**: 형식 버전 `2.1.299` 기준으로 만들고, 모르는 줄·필드는 건너뛰며 S3에 건너뛴 줄 수와 형식 버전을 보여 줘서 형식이 바뀐 것을 사용자가 알아챌 수 있게 해요. 일지에 꼭 필요한 값(`timestamp`, `cwd`, `sessionId`)이 없는 요청·답변 줄만 버려요. 제목 줄(`custom-title`·`ai-title`)처럼 시각·작업 폴더가 없는 요약 재료 줄은 `sessionId`로 세션에 붙여 써요.
    - 한 사람의 기록에도 여러 형식 버전이 섞이는 것이 정상이에요(2026-10-20 실제 기록에서 27개, A17). 그래서 S3 `[알림]`은 기준보다 새 버전이 있을 때만 띄우고 그중 가장 새 버전을 보여 줘요. 기준보다 옛 버전은 `[알림]` 없이 기록 형식 칸에 "옛 형식 파일 N개 · 건너뛴 줄 N개"처럼 수만 보여 줘요. 가장 옛 버전을 경고로 보여 주면, 섞인 것이 정상인데도 형식이 바뀐 것처럼 읽혀서예요. (실제 기록 시험 결과로 정했어요, 2026-10-20. "옛 형식"을 파일 수로 세는 것은 Q20, 사용자 확인 2026-10-20)
    - 이번에 처음 본 줄 종류 13가지 중 `ai-title`은 요약 재료로 쓰고(A5), 나머지 12가지(A17)는 일지 재료가 아니에요(2026-10-20). 그중 `pr-link`는 보관본에 남겨요(A7, Q19). 이 12가지는 아는 줄로 보고 건너뛴 줄 수에 세지 않아요. 건너뛴 줄 수가 형식이 바뀐 신호로 남으려면 이미 아는 줄 종류는 세지 않아야 해서예요. (Q20, 사용자 확인 2026-10-20)
    - 건너뛴 줄 수에는 모르는 줄 종류, 읽을 수 없는 줄, 꼭 필요한 값(`timestamp`·`cwd`·`sessionId`)이 없어 버린 요청·답변 줄을 합쳐 세고, S3에서 이유별로 나눠 보여 줘요(0인 이유는 빼요). 셋 다 형식이 바뀌었다는 신호라서예요. 모르는 줄 종류만 세면, 칸 이름이 바뀌어 요청·답변 줄이 버려질 때를 사용자가 알아챌 수 없어요. (취합 6회차 차이 1, 사용자 확인 2026-10-20)

  - **A16 보관본 다시 가리기**: 보관은 늘어난 부분만 더해서, 나중에 더한 사용자 패턴이나 바뀐 내장 규칙은 이미 보관한 줄에 닿지 않아요. 그래서 F2에 보관본 다시 가리기를 넣었어요(새 기능 번호는 만들지 않았어요). 원본이 지워진 보관본에도 동작하고, 그 보관본으로 만든 일지(이미 만든 일지 포함)에도 반영돼요. (사용자 확인 2026-10-20)
    - 사용자가 직접 실행해요. 사용자 패턴이 바뀌어도 일지 만들기·보관 때 자동으로 하지 않고, 검사(S4)에서 남은 의심이 나오면 이 동작을 안내해요. (Q18, 사용자 확인 2026-10-20)
    - 실행하면 먼저 바뀔 보관본·일지 파일마다 바뀔 자리 합계와, 전체 바뀔 자리의 종류별 합계(사용자 패턴은 패턴별)를 보여 주고(값은 보여 주지 않아요), 사용자가 확인해야 실제로 다시 써요. `--yes`를 주면 확인 없이 바로 실행해요. 확인을 거절하면 아무 파일도 바뀌지 않아요. 확인 출력과 결과는 S3에 나와요. (Q17, 사용자 확인 2026-10-20. 출력 모양 "파일별 합계 + 전체 종류별"은 취합 4회차 결정)

    - 아래는 사용자 확인 2026-10-20(취합 4회차 차이 목록에 대한 결정)이에요.
      - 바뀔 파일은 줄이지 않고 모두 보여 줘요. 너무 넓은 패턴이면 목록이 길어지는데, 그것 자체가 패턴을 다시 보라는 신호예요.
      - 확인 질문은 `y`·`yes`·`예`·`네`만 확인으로 받고, 그냥 Enter와 그 밖의 답은 모두 거절이에요.
      - `--yes`는 다시 가리기 명령에서만 받아요. 다른 명령에 주면 다시 가리기를 했다고 오해할 수 있어서 사용법 오류로 멈춰요(종료 코드 1).
      - 다시 가리기로 못 고치는 경우가 있어요. 가림 표시만 늘리고 나머지 내용을 지키려는 거예요.

  - **A20 세션 없는 저장소 안내**: 세션이 한 번도 없던 저장소의 커밋이 말없이 빠졌고, S3에는 `저장소 2개`만 나와 `--root`·`roots`를 써야 들어온다는 힌트가 없었어요. 빠진 줄 모르고 일지를 믿게 돼요. (사용자 결정 2026-10-21로 넣었고, 아래 세부는 기획에서 정했어요.)

  - **A21 이미 있는 일지 다시 만들기와 손으로 고친 일지**: 이미 일지가 있는 날짜를 다시 만들면(예: `--root`를 붙여 어제 일지 다시 만들기) 기존 마크다운·화면용 일지 데이터를 말없이 덮어써서, 마크다운에 손으로 적은 메모가 사라졌어요. (사용자 결정 2026-10-21로 넣었고, 아래 세부는 기획에서 정했어요.)
    - 손으로 고친 일지 마크다운은 어떤 일지 만들기(`--date`·`--from`·기본 실행, 다시 가리기·검사가 보여 준 다시 만드는 명령 포함)도 덮어쓰지 않아요. 그 날짜는 마크다운과 화면용 일지 데이터를 둘 다 그대로 두고(한쪽만 바뀌지 않게, 5장) 건너뛰며, S3에 `[알림]`으로 날짜를 모두 보여 주고 "메모를 다른 곳에 옮긴 뒤 그 `.md` 파일을 옮기거나 지우고 다시 실행하면 새로 만들어져요"라고 안내해요. 건너뛰는 것은 실패가 아니라서 종료 코드는 그대로예요. 다시 가리기가 일지 마크다운을 다시 만들지 않고 조각만 고치는 것도 손으로 고친 줄을 지키려는 거였어요(A16). 같은 원칙을 일지 만들기에도 써요.
    - 다시 만들게 하는 옵션(`--force` 같은)은 따로 두지 않아요. 마크다운을 옮기거나 지우면 "일지가 없는 날짜"가 되어 어느 방식으로든 새로 만들어지고, 옵션을 늘리지 않아도 돼요.
    - "손으로 고친"은 도구가 마지막으로 쓴 마크다운(일지 만들기나 다시 가리기가 쓴 내용)과 지금 내용이 조금이라도 다른 것이에요. 편집기가 줄 끝 모양만 바꾼 것도 고친 것으로 봐요(안전 쪽). 비교에 쓰는 값은 화면용 일지 데이터에 해시로만 두고 원문을 따로 남기지 않아요(5장). 이 값이 없는 일지(이 규칙 전에 만든 일지)는 고쳤는지 알 수 없어서 고치지 않은 것으로 봐요. 아직 공개 전이라 그런 일지는 시험용 데이터 폴더에만 있고, 한쪽만 가려진 일지를 다시 만들어 고치는 길(A16)을 막지 않으려는 거예요.
    - 다시 가리기가 손으로 고친 일지 마크다운의 조각을 고쳐도 손으로 고친 일지로 남아요. 다시 가리기 뒤의 일지 만들기가 메모를 덮어쓰지 않게 하려는 거예요. 손으로 고치지 않은 일지는 다시 가리기 뒤에도 고치지 않은 일지예요.
    - 사본은 남기지 않아요. 옛 내용 사본(백업)은 놓친 비밀 값을 남기고(A16, "옛 내용 백업은 남기지 않아요"), 새 내용을 다른 이름 파일로 두면 날짜마다 파일 하나(F1)·화면(S1·S2)과 어긋나요. 손으로 고친 마크다운은 사용자 파일이라 도구가 지우거나 옮기지 않고, 메모와 새 일지를 합치지도 않아요.
    - 손으로 고치지 않은 일지는 지금처럼 다시 만들어요. 고친 것이 없어 잃는 것이 없으므로 경고가 아니라 S3 결과에 "다시 만듦"으로 알려요(날짜 하나면 이미 있던 일지를 새 내용으로 바꿨다는 말, 여러 날이면 수). 오늘 일지는 실행마다 다시 만드는 것이 보통이라 `[알림]`으로 띄우지 않아요.
    - `--date`·`--from`으로 다시 만들며 이름·이메일 가리기가 켜져 있던 일지를 끈 채로 만들었으면, 그 날짜를 `[알림]`으로 알리고 `--hide-identity`를 붙여 다시 만드는 법을 보여 줘요. 공개용 일지가 말없이 이름·이메일이 드러난 일지로 바뀌는 것도 덮어쓰기로 잃는 것이라서예요. 일부러 끄는 경우도 있어서(같은 보관본으로 두 가지를 모두 만들 수 있음, A10) 막지는 않아요. 기본 실행은 이 경우가 생기지 않아요(A18).

    - 켜는 방법: 일지 만들기(`cc-worklog`, `cc-worklog make`)의 `--summary`와 `config.json`의 `"summary": true`로 켜요(Q27 답, 사용자 확인 2026-10-22). 둘 다 없으면 꺼져 있어요(기본). `config.json`의 `summary`는 일지 만들기에만 쓰이고, 다른 명령(`archive`·`check`·`redact`·`view`)에 `--summary`를 주면 사용법 오류로 멈춰요(종료 코드 1, A22). 보관만 하고 요약했다고 오해하지 않게 하려는 거예요(`--yes`·`--from`과 같은 까닭, A16·A18). 켜 둔 설정을 한 번만 끄는 옵션은 두지 않아요(`hideIdentity`와 같아요).
    - 요약하는 세션: 이번 실행이 쓰는 일지(새로 만듦·다시 만듦) 중 요약을 켠 일지(A28)의 세션이에요.
      - 날짜 옵션 없는 기본 실행도 요약을 켰으면 이번 실행이 쓰는 모든 일지를 요약을 켠 일지로 만들어요. 일지가 없던 지난 날짜(A18 ①)도 들어요. 대신 실행마다 `claude` 실행 수에 상한을 두고, 남은 세션은 다음에 요약을 켠 실행이 이어서 채워요. (Q26 답 (다), 사용자 확인 2026-10-22. 아래 세부는 기획에서 정했어요.)
        - 상한: 실행마다 `claude`를 50번까지 실행해요. 세션 하나·날짜 하나에 한 번이라(A25) 세션 50개예요. 성공·실패와 상관없이 실제로 실행한 수로 세고, 저장해 둔 요약을 다시 쓰는 세션과 부르지 않는 세션(아래)은 세지 않아요. 50번째를 시작하면 더 시작하지 않고, 이미 시작한 호출은 끝나기를 기다려요(A26의 60초 안).
          - 재료(가린 보관본의 그날 글, A25)를 만들지 못해(보관본을 읽지 못함 등) `claude`를 실행하지 않은 세션도 상한에 세지 않아요. 그만큼 다음 세션을 불러 실제 실행 수가 50이 될 때까지 채워요. 그런 세션은 요약하지 못한 세션(이유는 그 밖의 실패)으로 세고, 다음에 요약을 켠 실행이 다시 불러요. 이렇게 더 부른 세션이 다시 만들지 않기로 했던 요약 일지(A18 ③)에 있으면 그 일지도 다시 만들어 받은 요약이 일지에 들어가야 해요(방법은 개발이 정해요). 찾지 못함·로그인 안 됨·사용량 제한으로 남은 세션을 부르지 않는 경우(A28)는 지금처럼 실행 수가 50에 못 미쳐도 멈춰요. (취합 20회차 차이 1, 사용자 결정 2026-10-23)
          - 50으로 정한 까닭: 하루 세션 수(2026-10-20 실제 기록은 약 한 달 치 세션 466개, 하루 평균 십수 개)보다 넉넉해 매일 하는 실행은 오늘 일지를 한 번에 채우고, 동시에 2개·한 번에 60초(A26)라 모두 시간 초과여도 요약에 쓰는 시간이 약 25분을 넘지 않으며, 사용량도 실행마다 Haiku 호출 50번 이하로 미리 알 수 있어요.
        - 고르는 순서: 부를 세션이 상한보다 많으면 날짜가 늦은 일지의 세션부터 불러요. 같은 날짜 안에서는 그날 마지막 줄 시각이 늦은 세션부터, 같으면 세션 아이디 순이에요. 오늘 일지가 먼저 채워지고, 지난 날짜가 많이 남아 있어도 매일의 새 일지가 밀리지 않게 하려는 거예요.
        - 이어서 채우기: 다음에 요약을 켠 실행은 저장해 둔 요약이 있는 세션(그날 줄이 늘지 않음)은 다시 부르지 않고(A27), 요약이 빈 요약 대상 세션만 같은 순서로 불러요. 기본 실행은 이를 위해, 요약을 켜고 만든 일지 중 요약이 빈 세션이 남았고 그 세션이 이번 상한 안에 든 일지를, 그날이 끝난 뒤 만든 일지여도 다시 만들어요(A18 ③). 요약이 빈 까닭(상한으로 미룸, 찾지 못함·로그인 안 됨·사용량 제한으로 부르지 않음, 불렀다 실패함, 요약을 끈 실행이 비움(A28))과 상관없이 모두 이어서 채워요. 같은 세션이 되풀이해 실패하면(형식이 다른 결과 등) 실행마다 다시 불러 상한 중 그만큼을 쓰지만, 드물다고 보고 실패 횟수를 따로 남기지 않아요. 날짜가 늦은 세션부터 부르므로 새 일지가 그 때문에 밀리지는 않아요.
        - `--date`·`--from`과 함께 켜도 같은 상한과 순서예요(그 기간 안에서 최근 날짜부터). 기간이 길면 같은 까닭으로 한 실행에 다 부르지 않아요. 남은 세션은 같은 명령을 다시 실행하거나, 다음에 요약을 켠 기본 실행(A18 ③)이 이어서 채워요.
        - 상한을 바꾸는 설정(옵션·`config.json`)은 두지 않아요. 모델을 고정한 것(Q28)처럼 설정을 늘리지 않으려는 거예요. 더 빨리 채우려면 다시 실행하면 되고, 사용량을 더 줄이려면 요약을 끄면 돼요.
        - 알리기(S3): 이번 실행 뒤에도 요약이 빈 채 남은 세션이 있으면 그 세션 수와 그 일지(날짜) 수, 상한에 닿았는지, 다음에 요약을 켜고 실행하면 최근 날짜부터 이어서 채운다는 것을 한 줄로 보여 줘요. 기본 실행이면 이번에 다시 만들지 않은 요약 일지에 남은 세션도 더해 전체 남은 수예요. 손으로 고친 일지(A21)의 세션은 이어서 채우지 않아서 세지 않아요. 남은 세션이 없으면 이 줄은 없어요. 위험이 아니라 예상한 동작이라 `[경고]`가 아니고, 정확한 문구·자리는 디자인이 정해요.
          - "상한에 닿음"은 이번 실행에서 `claude`를 50번 실행했고, 부를 세션이 더 남았다는 뜻이에요. 부를 세션에는 기본 실행이 이번에 다시 만들지 않은 요약 일지(A18 ③에서 상한 안에 든 세션이 없어 빠진 일지)의 빈 세션도 들어요. 그래서 50번째 세션이 한 일지의 끝에 딱 맞아 남은 세션이 다시 만들지 않은 일지에만 있어도 상한에 닿은 거예요. 재료를 만들지 못해 실행하지 않은 세션은 50번에 세지 않아요(위 상한). 50번을 다 실행하지 않고 남은 세션(이번에 불렀다 실패한 세션만 남음, 찾지 못함·로그인 안 됨·사용량 제한으로 멈춤)은 상한에 닿은 것이 아니에요. 왜 남았는지 사용자가 알 수 있게 하려는 거예요(취합 20회차 차이 2, 사용자 결정 2026-10-23).

    - 한계: 요약은 가린 재료로만 쓰여서, 요약에 새로 들어갈 수 있는 비밀 값은 보관본에 이미 남아 있던(규칙이 놓친) 값뿐이에요. 다만 AI가 그 값을 다른 모양으로 바꿔 쓰면 규칙이 놓칠 수 있어서, 형식 없는 비밀처럼 S4의 "놓칠 수 있는 것" 줄과 README에 적어요.

      - 새로 만드는 일지와 `--date`·`--from`으로 다시 만드는 일지는 이번 실행 설정을 따라요(요약을 켠 기본 실행은 새로 만드는 지난 날짜도 요약을 켠 일지로 만들고, 상한(A24)을 넘는 세션은 요약을 비워 두었다가 다음 실행이 이어서 채워요, Q26 답). 요약을 켜고 만든 일지를 끈 채로 다시 만들면 요약 줄이 빠져요. 요약 저장 파일은 남아서, 다시 켜고 만들면 그날 줄이 늘지 않은 세션은 새로 부르지 않고 같은 요약이 돌아와요. 잃는 것이 없어서 경고 대신 S3에 그런 날짜 수와 `--summary`로 다시 만드는 법을 한 줄로 알려요.
      - 기본 실행이 A18 ②·③으로 다시 만드는 일지는 그 일지나 이번 실행 중 한쪽이라도 요약이 켜져 있으면 요약을 켠 일지로 만들어요(③은 요약을 켠 실행에만 있어요). 저녁에 `--summary`로 만든 일지가 다음 날 아침 기본 실행에서 요약 없는 일지로 바뀌지 않게 하려는 거예요. 이번 실행이 요약을 끈 실행이면 `claude`를 부르지 않고 요약 저장 파일에서 그날 줄이 늘지 않은 세션만 채우며, 새 세션·줄이 늘어난 세션은 요약 줄을 비워요. 이렇게 비운 세션도 요약이 빈 세션이라 다음에 요약을 켠 실행이 이어서 채워요(A18 ③, A24). 요약을 끈 기본 실행은 요약이 빈 채 남은 요약 일지가 있으면 S3에 그 세션 수(이렇게 비운 세션 포함)와 `--summary`로 실행하면 이어서 채운다는 것을 한 줄로 알려요.
      - 다시 가리기·검사가 보여 주는 다시 만드는 명령(A16)은 그 일지를 요약을 켜고 만들었으면 `--summary`를 붙여요. 빼면 요약 줄이 빠진 일지로 바뀌어서예요. 저장해 둔 요약을 다시 쓰므로 대개 새로 부르지 않아요.
      - 요약을 그만 쓰려면(회사 정책 등) `config.json`의 `summary`를 지우고, 요약을 켜고 만든 일지를 `--from`으로 다시 만들면 요약 줄이 빠져요. 요약 저장 파일은 데이터 폴더에서 지우면 돼요. README에 적어요.
