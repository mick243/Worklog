## 항목 자세히

### I-01 `check`가 이름·이메일을 가리지 않은 일지를 `[통과]`로만 끝내요 (PRD 반영, 미구현)

- 근거:
  - PRD F2·S4·A19(2026-10-21): 옵션이 꺼진 일지에 남은 사용자 이름·이메일도 값 없이 세어 보여 주고, 하나라도 있으면 판정 줄 가까이에 `[알림]`(옵션을 끈 일지 수, 남은 수, `[통과]`는 비밀 값 기준, `--hide-identity`로 다시 만들라는 안내)을 보여 줘요. "옵션이 꺼져 있어 세지 않았어요"만 보여 주지 않아요. 판정·종료 코드는 그대로예요. S3 검사 줄에도 이름·이메일을 가리지 않았다는 말을 더해요.
  - 코드: `app/src/commands/check.ts` 158행이 옵션이 켜진 일지만 세요(`idOn`). `app/src/term/s4-check.ts` 155~157행이 "옵션이 꺼져 있어 세지 않았어요"를 찍어요. `app/src/term/s3-summary.ts` 221행 검사 줄은 늘 같은 글이에요.
  - 문서: `docs/DESIGN.md` S4 5번(1079행)과 예시(1154·1247·1273·1288행)가 아직 "옵션이 꺼져 있어 세지 않았어요"이고, A19의 `[알림]`·S3 검사 줄 덧붙임 모양이 없어요.
  - 재현: 가짜 홈에 세션 요청 글에 가짜 이메일과 작업 폴더 경로가 든 세션을 두고 `cc-worklog` → `cc-worklog check`. 일지 마크다운에 이메일과 경로 속 사용자 이름이 그대로인데 `이름·이메일 (일지만)  옵션이 꺼져 있어 세지 않았어요` / `[통과] 남은 의심 0건, 놓친 패턴 0개`(종료 코드 0)로 끝났어요. 같은 데이터를 `check --hide-identity`로 보면 사용자 이름 8건·이메일 2건이 나와요.
- 지금: S3가 "공개 전에 check로 확인하세요"라고 하고, check는 `[통과]`만 보여 줘서 통과를 보고 공유하면 이메일·경로가 나가요. 피드백이 "가장 위험"으로 꼽았어요.
- 기대: 옵션을 끈 일지의 이름·이메일 수와 `[알림]`이 판정 가까이에 나오고, 일지 만들기 S3 검사 줄도 같은 뜻을 알려요. 판정·종료 코드는 그대로예요.
- 해결 기준: 이름·이메일 가리기를 끄고 만든 일지에 경로 속 사용자 이름·이메일이 남은 가짜 데이터로 `check`를 실행하면 `이름·이메일 (일지만)` 칸에 실제 수(값 없이)와 판정 줄 가까이 A19 `[알림]`이 나오고 종료 코드는 0이며, 그 일지를 만든 일지 만들기의 S3 검사 줄에 "이름·이메일을 가리지 않았고 공개하려면 `--hide-identity`" 뜻이 더해지고, DESIGN S3·S4에 같은 문구가 있다.

### I-02 세션이 없던 저장소의 커밋이 말없이 빠져요 (PRD 반영, 미구현)

- 근거:
